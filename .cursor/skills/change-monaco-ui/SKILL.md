# Изменение Monaco UI

Прочитай `docs/project-index.md`, `.cursor/rules/project-core.mdc` и `.cursor/rules/monaco-web.mdc`. Начни с `git status`: каталог `src/code/` может содержать пользовательские незакоммиченные файлы.

## Найти контракт

Определи точку входа в `index.html`, регистрацию в `editor.js`/`bsl_language.js` и вызовы из `Forms/Основная/Ext/Form/Module.bsl`. Публичными считай методы и свойства, доступные через `defaultView`, DOM-события и известные форме идентификаторы элементов.

## Изменить

Правь минимальный набор файлов. Не изменяй vendored Monaco в `src/code/vs/` и большие справочники `bslGlobals.js`/`bslMetadata.js`, если задача не про их обновление. Не добавляй внешнюю сеть или новый build tool без отдельного решения. Учитывай повторную инициализацию: providers, actions, listeners и models не должны накапливаться.

## Синхронизировать пакет

Форма исполняет ZIP `Templates/src/Ext/Template.bin`, а не каталог `src/code/` напрямую. До упаковки сравни состав и хэши, выясни назначение `src2`, затем синхронизируй только выбранный runtime-пакет воспроизводимым способом. Не затирай архив вслепую и не объявляй рабочую копию источником истины без фиксации этого решения в документации.

## Проверить

Проверь автономную загрузку `index.html`, создание редактора, ввод и получение текста, затронутое action/provider, событие в форме и повторное открытие. Для ошибки JavaScript проверь видимую диагностику в 1С. После упаковки снова сравни содержимое ZIP, затем выполни `git diff --check` и просмотри бинарный и текстовый diff отдельно.
