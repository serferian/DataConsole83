# Изменение внешней обработки

Сначала прочитай `docs/project-index.md`, `.cursor/rules/project-core.mdc` и `.cursor/rules/bsl-epf.mdc`. Проверь рабочее дерево и не включай несвязанные изменения.

## Анализ

Найди команду или событие в `Form.xml`, соответствующий обработчик в модуле формы и весь путь до серверной операции. Зафиксируй границу клиент/сервер, используемые адреса временного хранилища, структуру результата и вызываемый JavaScript API. Для дефекта сначала воспроизведи сценарий или докажи ветку по коду.

## Реализация

Вноси минимальное изменение в распакованные исходники `src/epf/DtCons83Monaco/`. Сохраняй сигнатуры обработчиков, директивы компиляции, безопасный режим динамического кода и совместимость сохраненных алгоритмов. XML меняй только если действительно меняется форма или метаданные; не переформатируй его целиком.

Если изменение затрагивает вызов `View()`, `QueryView()` или `CodeView()`, одновременно проверь контракт в `src/code/` и используй skill `change-monaco-ui` для web-части.

## Проверка

Подбери различающий сценарий: обычный результат, пустой результат, ошибка и повторный запуск. Для клиент-серверного или фонового кода проверь оба контекста и очистку ресурсов. Для UI сформулируй BDD-сценарий и выполни его в целевом клиенте, если окружение доступно.

Сверь `git diff`, выполни `git diff --check`. Репозиторные cmd-скрипты используют старый синтаксис `vrunner`; перед сборкой проверь версию. На `vanessa-runner 3.x` ориентируйся на `vrunner epf compile --help`. Не сообщай об успешной сборке без нулевого exit code и свежего артефакта.
