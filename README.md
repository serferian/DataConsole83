# Консоль запросов для 1С с редактором на базе Monaco

DataConsole83 — внешняя управляемая обработка `DtCons83Monaco` для исследования данных и выполнения BSL-кода в 1С:Предприятии 8.3. Редактор Monaco встроен в HTML-документ и дает подсветку BSL и языка запросов, подсказки, сниппеты, навигацию, diff и отображение ошибок.

Пользовательские сценарии и все команды консоли описаны в [руководстве пользователя](docs/code-console-user-guide.md). Подробная карта модулей, потоков и интеграционных контрактов находится в [индексе проекта](docs/project-index.md). Правила для AI-агентов описаны в [AGENTS.md](AGENTS.md) и `.cursor/rules/`.

## Возможности

- дерево алгоритмов с сохранением в файл и восстановлением;
- конструктор запроса, выполнение выделенного фрагмента и пакета запросов;
- просмотр результатов и временных таблиц с переходом к тексту запроса;
- статистика и замеры выполнения;
- выполнение BSL на клиенте, сервере и в фоновых заданиях;
- обработка результата на форме и сниппеты;
- отображение ошибки в строке кода и просмотр значений переменных;
- выгрузка и загрузка результатов в CSV, TXT и dump;
- просмотр таблиц значений, деревьев и данных из хранилища.

## Архитектура

```text
Форма 1С (BSL/XML)
    ↕ defaultView, DOM-события
HTML + Monaco + BSL language services
    ↕ ZIP runtime-пакет
Templates/src/Ext/Template.bin
```

- `src/epf/DtCons83Monaco/` — распакованные исходники внешней обработки.
- `src/code/` — рабочее дерево HTML, CSS, JavaScript и Monaco.
- `tools/` — Windows-скрипты сборки и разбора EPF.
- `.build/` — локальная файловая ИБ и артефакты; каталог не коммитится.

Исполняемая обработка извлекает web-файлы из `Templates/src/Ext/Template.bin`. Изменения в `src/code/` сами по себе не попадают в EPF: перед сборкой нужно осознанно синхронизировать ZIP и проверить его состав.

## Сборка

Требуются установленная платформа 1С, OneScript и `vanessa-runner`. Репозиторные скрипты используют файловую ИБ `.build/ibservice`:

```powershell
tools\compileEpfErf.cmd src\epf\DtCons83Monaco
tools\decompileEpfErf.cmd ".build\DtCons83Monaco.epf"
```

Скрипты написаны для плоских команд `vrunner compileepf/decompileepf`. В `vanessa-runner 3.x` синтаксис изменен на `vrunner epf compile/decompile`; доступные параметры проверяются командами:

```powershell
vrunner epf compile --help
vrunner epf decompile --help
```

Не используйте разбор EPF поверх рабочего дерева без просмотра `git status`: операция может перезаписать распакованные XML и BSL.

## Разработка и проверка

Перед изменением определите затронутый контракт на обеих сторонах: обработчик формы 1С и функцию/событие JavaScript. Не редактируйте vendored `src/code/vs/`, если задача не состоит в обновлении Monaco.

Минимальная статическая проверка:

```powershell
git status --short
git diff --check
git diff --stat
```

Автоматизированный тестовый контур пока не настроен. `src/code/test.html` ссылается на отсутствующий `test.js`, поэтому этот файл нельзя считать готовым runner. Изменения редактора проверяются внутри целевого клиента 1С: загрузка, ввод/получение текста, команда, событие, вывод ошибки и повторное открытие формы. Изменения запросов и выполнения кода должны различать успешный результат, пустой результат и ошибку.

## Фоновое выполнение

Для интеграции с конфигурацией требуется экспортная процедура, которую вызывает механизм длительных операций. Она должна устанавливать безопасный режим до выполнения переданного алгоритма:

```bsl
Процедура ВыполнитьВБезопасномРежиме(Знач Параметры, АдресРезультата = Неопределено) Экспорт
	Перем Алгоритм, ДополнительныеПараметры;

	УстановитьБезопасныйРежим(Истина);
	Параметры.Свойство("Алгоритм", Алгоритм);
	Параметры.Свойство("ДополнительныеПараметры", ДополнительныеПараметры);

	Если Не ЗначениеЗаполнено(Алгоритм) Тогда
		Возврат;
	КонецЕсли;

	Выполнить Алгоритм;
КонецПроцедуры
```

Конкретное размещение процедуры и запуск длительной операции зависят от конфигурации, в которую подключена обработка.
